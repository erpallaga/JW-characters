# Tech Stack

Single-file frontend, no build step, no package.json/node_modules. Language: JS + inline styles in one HTML doc.

- `index.html` — entire app: markup template (`<x-dc>` custom root tag), inline `<style>`, and a
  `<script type="text/x-dc" data-dc-script data-props="...">` block holding a React-class-like component
  (uses `this.state`, `this.setState`, `renderVals()`) plus static data (`ERAS`, `CHARACTERS` arrays).
- `support.js` — GENERATED runtime (from an external `dc-runtime` TS project via `bun run build`, not present
  in this repo). Parses the `<x-dc>` template/props/JS, wires up `window.React`/`window.ReactDOM`. Never hand-edit
  (file header says so) — regenerate upstream instead.
- `image-slot.js` — copied "omelette starter component" (`<image-slot>` custom element) for droppable/persisted
  images. Also regenerated by an external tool (`copy_starter_component`) — treat as vendored, not hand-authored.
- `.image-slots.state.json` — sidecar persisted by `<image-slot>` drops (document-relative, sibling of the HTML
  using it). Not meant for manual editing.
- Google Fonts (Amiri, Mulish) loaded via CDN link tags; no local font assets.
- `assets/mapa-*.png` — one background map image per Bible character, referenced by `mapSrc` in the `CHARACTERS`
  data array in index.html.
- Root-level `*.pdf` files (`ia_S.pdf`, `lfb_S.pdf`, `wcg_S.pdf`, `502xxxxxx_S_cnt_1.pdf`) — JW.org source
  publications, reference material for character write-ups, not consumed programmatically.
- `docs/superpowers/` — spec + plan docs from the original build (superpowers skill artifacts), e.g.
  `docs/superpowers/specs/2026-08-08-bible-character-flashcards-design.md`.

See `mem:conventions` for data-array and styling conventions.
